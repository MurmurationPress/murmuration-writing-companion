# V2 onboarding and example-vault manual validation

Use copies extracted from the deterministic example archive. Record checksums or Git status before and after each read-only onboarding action.

## Prepared example

1. Open `prepared-vault` as its own Obsidian vault and enable MWC.
2. Confirm the first-run invitation waits until metadata is ready and appears once.
3. Dismiss it, reload the plugin and confirm it does not repeat; run **Open project readiness** manually.
4. Confirm readiness reports one prepared Book, two Parts, five Scenes, eight Story World entities and two Events.
5. Open **Manuscript** and confirm: Opening at Greywater; Listening → First Survey, Signal at Low Tide; Returning → Return to the Observatory, The Recorded Pattern.
6. Open Story World Navigator and inspect all entity categories and Mara's alias.
7. Select Mara Venn and Return Survey in Entity Inspector and Story World Graph; confirm relationship and source navigation.
8. Open Story World Review and confirm the deliberately unresolved calibration-sheet source is reported.
9. Open Continuity Review for The Greywater Signal and confirm relevant explicit Story World evidence is available.
10. Run **Generate entity index**, choose Vault, include Reference and preview/save only inside the disposable copy.
11. Confirm there is no **Generate references report** command; inspect Greywater Hydrophone Log and its `world_sources` instead.
12. Confirm readiness open, recheck and dismissal changed no Markdown or editorial data.

## Migration example

13. Open a fresh `migration-vault` copy. Confirm readiness reports preparation available for The Low Water Ledger.
14. Use the visible **Prepare manuscript** action. Confirm the preview includes one Book, two Parts, five Scenes and every exact property operation.
15. Approve preparation. Confirm filenames, folders, prose and every `demonstration_note` remain unchanged; confirm the legacy array is absent only after verified child writes.
16. Run **Undo manuscript preparation** immediately. Confirm every source file is byte-for-byte identical to the extracted copy.
17. Prepare again and confirm a second preparation analysis is no-change; Undo or discard the disposable copy.

## Safety and reset

18. Confirm no file outside the opened example vault changed.
19. Reset by deleting the disposable copy and extracting a fresh archive. Never reset by bulk-removing structural metadata.
20. Follow the [screenshot checklist](v2-onboarding-screenshot-checklist.md) during #160 on supported Obsidian versions and the required Windows/Linux matrix.

Also ask a technically capable Obsidian user without repository knowledge to follow the [onboarding guide](v2-onboarding-guide.md) from the release package. Record any step that requires source-code or GitHub knowledge as a documentation defect.
